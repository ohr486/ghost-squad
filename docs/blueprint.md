## 1. プロダクト・ビジョン

「電脳世界の特殊部隊（Ghost-Squad）と共に、最高のプロダクトを最速でビルドする。」

ユーザーは司令官（Commander）として、自律型AIエージェントの群れ（Squad）を指揮する。AIはタチコマのように並列化して知能を共有し、Aチームのように圧倒的な突破力で課題を解決する。

自律型AI（Ghost）の並列思考と、人間（Commander）の直感を融合。リソース管理を徹底しながらも、圧倒的な突破力を持つ次世代の開発支援プラットフォーム。

## 2. インターフェース要件

### A. Living Kanban (Web GUI)

- デザイン: クリーン・モダン（白ベース、シンクロ・ブルーのアクセント）。

- 動的ステート: AIが自律的にカードを移動。ドラッグ＆ドロップによるユーザーの「権限強奪（Override）」が可能。

- 承認パネル: 予算超過やプランB提示時に、グラスモーフィズムなオーバーレイで介入を要請。

### B. Ghost-Terminal (CLI/TUI)

- アイデンティティ: gs コマンドによる高速操作。

- リッチ表示: ASCIIアートによるミッションロゴ、エージェントごとのカラーログ、リアルタイムな進行バー（TUI）。

- ライブ同期: Web GUIの変更が数ミリ秒でターミナルにも反映。

## 3. インテリジェンスと記憶

### 1. 共有知能（Shared Ghost-Memory）

- プロジェクト特化型メモリ: ミッションごとの知見をベクトル化し、エージェント間で並列化（Sync）。

### 2. 自律実行と権限管理

- プランBエンジン: 予算・技術的制約で行き詰まった際、代替案を自動生成。

- 権限レベル設定: 実行可能なアクション（GitHub操作、デプロイ、API実行等）を細分化して管理。

### 3. ポストモーテム

- デブリーフィングレポート: 完了したタスクから「教訓」を抽出し、ナレッジとして蓄積。


## 4. リソース・トラッキング

エージェントの活動コストは以下の数式に基づき、リアルタイムに算出・表示されます。

$$TotalCost = \sum_{i=1}^{n} (Usage_{i} \times Rate_{model})$$

- n: エージェントが行った全APIコールの総数

- Usage: 入出力トークン量

- Rate: モデルごとの単価（USD）

- セーフティ: 設定された Limit に達した瞬間、プロセスを PAUSE 状態にし、司令官の承認を要求。

## 5. システム・アーキテクチャ 5つの柱

### 1. 共有知能プロトコル（Shared Ghost-Memory）

- プロジェクト特化型記憶: 各プロジェクトは独立したベクトルデータベースとコンテキストを持ち、機密性を担保。

- 知能の並列化（Sync）: 一つのエージェントが得た知見（バグの回避策や新仕様）は即座に全メンバーのプロンプトへ反映される。


### 2. 自律型オーケストレーション（Autonomous Execution）

- 動的スクワッド編成: タスクの性質（フロントエンド、インフラ、セキュリティ等）に応じて、最適な専門AIをその都度召喚。

- 権限管理マトリクス（Permission-Level）:

-- READ-ONLY: 提案のみ。

-- LIMITED: コード生成・ドキュメント作成まで。

-- FULL-AUTO: GitHubコミット、外部API実行、デプロイ（※司令官によるアクション別の許可設定が必要）。

### 3. リビング・カンバン UI（Living Board UX）

- 動的ステート管理: AIが自律的にカードを動かし、作業状況をリアルタイムに視覚化。

- プレイング・マネージャー介入: ユーザーがカードを掴んだ瞬間、AIは即座に所有権を譲渡しサポートに回る。

### 4. リソース・セーフティ（Energy Management）

- リアルタイム・トラッキング: 全APIコールをUSD換算で追跡し、カード単位・プロジェクト単位で表示。

- ハード・リミッター: 予算上限到達時に「帰還（ポーズ）」し、プランB（代替案）を提示して承認を待つ。

### 5. ポストモーテム報告（Mission Debriefing）

- 事後分析レポート: タスク完了時、AIが「発生した課題」「解決の経緯」「将来的な技術負債の懸念」を自動生成。

## 6. 主要な機能要件

| カテゴリ       | 要件詳細                                                                           |
|----------------|------------------------------------------------------------------------------------|
| 指示出し       | 曖昧な自然言語からAIが「作戦計画（WBS）」を自動生成。                              |
| プランB提案    | 行き詰まりや予算不足時に、AI同士で会議し「代替案」をボタン付きで提示。             |
| シンクロ・ログ | エージェント間のワチャワチャした通信内容を可視化し、チームの一体感を演出。         |
| 権限制御       | 「デプロイだけは人間が承認する」「プルリク作成まではAIがやる」等の微細な権限設定。 |


## 7. 技術要件 (Technical Specs)

- 通信プロトコル: WebSocket (Pub/Sub) による全インターフェースの即時同期。

- バックエンド: Python (FastAPI/LangGraph) によるステートフル・オーケストレーション。

- フロントエンド: Next.js, Framer Motion, dnd-kit。

- CLI: Rust または Go による高速なTUIレンダリング。

## 8. 非機能要件

- 低レイテンシ同期: WebSocket（Supabase Realtime等）による、ラグのないカード操作の同期。

- 高秘匿性: プロジェクトAの記憶がプロジェクトBに漏れない、完全なテナンシー分離。

- 拡張性: 新しいLLMモデル（GPT-5, Claude 4等）が登場した際、即座にエージェントの「魂」を入れ替えられるプラグイン構造。
