# Implementation Plan

- [x] 1. プロンプトのデータモデルとデータベーススキーマを作成する
  - プロンプトのカテゴリ分類（ストーリー生成、インポート解析、汎用）を列挙型として定義する
  - プロンプトの永続化モデルを作成する。キー（一意識別子）、名前、説明、カテゴリ、現在の本文、デフォルト本文、変数リスト（JSON）、デフォルトからの変更フラグ、編集ロック情報（編集者ID・開始日時）を持つ
  - Alembicマイグレーションでpromptsテーブルを作成し、key列にユニークインデックス、category列にインデックスを設定する
  - 既存のBaseModelパターンを継承し、created_at/updated_atタイムスタンプを含める
  - データモデルのユニットテストを作成する（フィールド制約、カテゴリ列挙型の値検証）
  - _Requirements: 1.1, 1.4, 4.3_

- [x] 2. プロンプトのデータアクセス層を実装する
  - キーによるプロンプト取得、全プロンプト取得（カテゴリフィルタリング対応）を実装する
  - プロンプト内容の更新機能を実装する。デフォルト本文は更新対象から保護し、更新時にis_modifiedフラグを自動計算する
  - デフォルト値へのリセット機能を実装する（現在の本文をデフォルト本文で上書き）
  - 編集ロック情報の更新機能を実装する（編集者ID、編集開始日時の設定・クリア）
  - シード用のプロンプト作成機能を実装する
  - 各操作のユニットテストを作成する（CRUD正常系・異常系、カテゴリフィルタリング、デフォルト保護検証）
  - _Requirements: 1.1, 1.2, 1.3, 2.2, 4.4_

- [x] 3. バリデーションとキャッシュ
- [x] 3.1 (P) プロンプト入力のバリデーション機能を実装する
  - プロンプト本文の空チェックを実装し、空の場合はGS-401エラーを返す
  - プレースホルダー構文の検証を実装する。`{variable_name}`形式の構文チェックと、許可された変数名リストとの照合を行い、無効な場合はGS-402エラーを返す
  - 無効なカテゴリ指定に対するGS-403エラーを実装する
  - 各バリデーションルールのユニットテストを作成する（正常系・異常系、エラーコード検証）
  - _Requirements: 2.3, 2.4_

- [x] 3.2 (P) TTL付きインメモリキャッシュ機能を実装する
  - キーベースのインメモリキャッシュをTTL（60秒）付きで実装する。TTL超過エントリはget時にNoneを返す
  - DB障害時フォールバック用のget_fallbackメソッドを実装する（TTL超過エントリも返却）
  - キャッシュの無効化（単一キー、全体）機能を実装する
  - TTL動作、キャッシュヒット/ミス、フォールバック、無効化のユニットテストを作成する
  - _Requirements: 5.5_

- [x] 4. プロンプト管理のビジネスロジック層
- [x] 4.1 プロンプトの取得・更新・リセットロジックを実装する
  - プロンプト取得のフォールバック戦略を実装する（キャッシュ → DB → デフォルト）
  - プロンプト一覧取得（カテゴリフィルタリング対応）を実装する
  - プロンプト更新の一連の処理を実装する（バリデーション実行 → DB更新 → キャッシュ無効化）
  - デフォルトリセット処理を実装する（本文をデフォルト値に戻し、キャッシュを無効化）
  - 各操作のユニットテストを作成する（キャッシュヒット/ミス/フォールバック、更新後キャッシュ無効化、リセット動作）
  - _Requirements: 1.1, 1.2, 1.3, 2.2, 2.3, 2.4, 4.4, 5.1, 5.2, 5.3, 5.4, 5.5_

- [x] 4.2 プロンプトのテスト実行機能を実装する
  - プロンプト本文のプレースホルダーを指定された変数値で置換し、AIプロバイダーに送信して結果を取得する
  - テスト実行時にAIプロバイダーを選択できるようにする（OpenAI/Anthropic、未指定時はデフォルト）。既存のAIProviderRegistryを活用する
  - テスト実行のタイムアウト（30秒）を設定し、超過時はGS-406エラーを返す
  - AI API呼び出し失敗時のGS-407エラーハンドリングを実装する
  - テスト実行のユニットテストを作成する（AIプロバイダーモック、タイムアウト、プロバイダー選択検証）
  - _Requirements: 3.1, 3.2, 3.4_

- [x] 4.3 編集ロック管理機能を実装する
  - 編集ロックの取得機能を実装する。他のユーザーが編集中の場合はGS-405エラーを返す
  - 編集ロックの解放機能を実装する
  - 30分経過した編集ロックの自動無効化判定を実装する（アプリレベル判定）
  - 編集ロックのユニットテストを作成する（取得・解放・競合・タイムアウト無効化）
  - _Requirements: 2.5_

- [x] 5. デフォルトプロンプトの定義とシード処理を実装する
  - ストーリー生成用のデフォルトプロンプトを定義する（現在StoryGenerationServiceにハードコードされているプロンプトを移行）
  - インポート解析用のデフォルトプロンプトを定義する（現在OpenAIProvider/AnthropicProviderのANALYSIS_SYSTEM_PROMPTを移行）
  - アプリ起動時（lifespan処理）に冪等なシード処理を実装する。既存プロンプトは上書きしない
  - デフォルト値はシステム定義として保護し、管理者による削除・上書きを禁止する
  - シード処理のユニットテストを作成する（初回投入、冪等性検証、既存データ保護）
  - _Requirements: 4.1, 4.2, 4.3_

- [x] 6. REST APIエンドポイント
- [x] 6.1 プロンプトの一覧・詳細・更新エンドポイントを実装する
  - プロンプト一覧取得エンドポイント（カテゴリフィルターパラメータ対応）を実装する
  - プロンプト詳細取得エンドポイント（キーによる取得、デフォルトからの変更有無を含む）を実装する
  - プロンプト更新エンドポイント（バリデーション、編集ロック競合時の409レスポンス）を実装する
  - PydanticスキーマでAPI入出力の型定義を行う（レスポンス、更新リクエスト、一覧レスポンス）
  - 各エンドポイントのAPIテストを作成する（正常系・異常系、HTTPステータスコード検証）
  - _Requirements: 1.1, 1.2, 1.3, 2.2, 4.5_

- [x] 6.2 テスト実行・リセット・編集ロックエンドポイントを実装する
  - テスト実行エンドポイント（プロバイダー選択対応、タイムアウト時の504レスポンス）を実装する
  - デフォルトリセットエンドポイントを実装する
  - 編集ロック取得・解放エンドポイントを実装する
  - PydanticスキーマでAPI入出力の型定義を行う（テスト実行リクエスト・結果、ロック取得リクエスト）
  - 各エンドポイントのAPIテストを作成する（テスト実行モック、タイムアウト、ロック競合）
  - _Requirements: 2.5, 3.1, 3.2, 3.4, 4.4_

- [x] 7. 既存サービス統合
- [x] 7.1 (P) ストーリー生成サービスのプロンプト取得元を切り替える

- [x] 7.2 (P) インポート解析プロバイダーのプロンプト取得元を切り替える
  - OpenAIProviderとAnthropicProviderのシステムプロンプトを、プロンプト管理サービスから取得するように変更する
  - 現在2つのプロバイダーに重複コピーされているプロンプトを一元化する
  - プロンプト管理サービスが利用不可の場合、既存の定数プロンプトにフォールバックする
  - 既存のインポート解析テストが引き続き通過することを確認する

- [x] 8. フロントエンド型定義とAPIクライアントを実装する

  - バックエンドAPIと通信するAxiosベースのAPIクライアントを実装する（一覧取得、詳細取得、更新、テスト実行、リセット、ロック操作）
  - エラーレスポンスのインターセプターを設定する（既存APIクライアントパターンに従う）
  - APIクライアントのユニットテストを作成する（各API操作、エラーハンドリング）

  - ローディング・エラー状態の表示を実装する

- [x] 9.2 プロンプト詳細・編集コンポーネントを実装する
